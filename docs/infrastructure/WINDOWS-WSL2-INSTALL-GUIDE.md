## Windows Native: Not Viable (Yet)

Building directly on Windows (without WSL2) was attempted first and abandoned due to multiple blockers:

### 1. Rust Workers: No Linker

Rust targets on Windows require a C linker:
- **GNU target** (`x86_64-pc-windows-gnu`): needs `dlltool.exe` from MinGW binutils
- **MSVC target** (`x86_64-pc-windows-msvc`): needs `link.exe` from Visual Studio Build Tools

Neither was present on a clean Windows install. The project doesn't document which target to use.

### 2. Unix Socket IPC Paths Broken

The IPC socket path gets mangled on Windows:
```
Expected: ~/.continuum/sockets/continuum-core.sock
Got:      C:\...\src\Users\tobye\.continuum\sockets\continuum-core.sock
```

Unix domain sockets work on Windows 10+, but the path construction in the codebase assumes POSIX paths.

### 3. Shell Scripts Incompatible

`npm start` invokes `.sh` scripts. On Windows, npm uses `cmd.exe` by default, which cannot execute shell scripts. All build scripts (`install.sh`, `parallel-start.sh`, `start-workers.sh`, etc.) are bash-only.

### 4. Missing Generated TypeScript Types

The `shared/generated/` directories (`ai/`, `code/`, etc.) are not checked into the repo. These are generated by `cargo test` running the `ts-rs` macros. Without a working Rust build, ~100+ TypeScript errors (`TS2307`, `TS2339`) occur.

**Recommendation**: Windows native support would require significant work (cross-platform path handling, PowerShell build scripts, pre-built binaries). WSL2 is the correct path for Windows users.

## WSL2 Installation: Step-by-Step

### What Worked

The following completed successfully on WSL2 Ubuntu 24.04:

1. **System dependencies**:
   ```bash
   sudo apt-get install -y build-essential pkg-config jq libssl-dev \
     libglib2.0-dev libasound2-dev cmake libclang-dev \
     protobuf-compiler libva-dev libnvidia-gl-535
   ```

2. **Node.js v24** (via nvm or nodesource)

3. **Rust 1.94.0** (via rustup)

4. **Python 3.12 venv** with PyTorch (CUDA) and ML packages

5. **PostgreSQL 16** — installed, database created, auth configured

6. **npm dependencies** — 727 packages installed cleanly

7. **Voice models** — Whisper large-v3-turbo, Piper TTS, Kokoro TTS, Silero VAD all downloaded

8. **Scene models** — 5 GLB files generated

9. **Node.js server partial start** — 17 daemons initialized, 319 command schemas loaded, WebSocket listening on port 9001

### Fixes Required During Install

#### PostgreSQL Authentication

PostgreSQL defaults to `peer` auth, which doesn't work for TCP connections. Fix:

```bash
# Add trust auth for local TCP connections
sudo sed -i '/^host.*all.*all.*127.0.0.1/i host    continuum       YOUR_USER        127.0.0.1/32            trust' \
  /etc/postgresql/16/main/pg_hba.conf
sudo service postgresql restart

# Verify
psql -h 127.0.0.1 -U YOUR_USER -d continuum -c "SELECT 1"
```

**Suggestion for install.sh**: Automate PostgreSQL setup including `pg_hba.conf` configuration.

#### Missing Barrel Exports in `shared/generated/`

Some generated type directories were missing their `index.ts` barrel files. Fix:

```bash
cd src/shared/generated
for dir in agent ai code dataset inference ipc live logger mcp orm plasticity rag search sentinel system; do
  if [ ! -f "$dir/index.ts" ]; then
    for f in "$dir"/*.ts; do
      name=$(basename "$f" .ts)
      if [ "$name" != "index" ]; then
        echo "export type * from './$name';" >> "$dir/index.ts"
      fi
    done
  fi
done
```

**Suggestion for install.sh**: Run barrel generation after `cargo test` generates the types.

#### TypeScript Build Errors

Two files had issues on a clean checkout:

1. **`GenomeTrainingOverviewServerCommand.ts`** — UUID import path used `@types/CrossPlatformUUID` alias which didn't resolve. Fixed by using relative import:
   ```typescript
   import type { UUID } from '../../../../system/core/types/CrossPlatformUUID';
   ```

2. **`GridOverviewWidget.ts`** — `GRID_STATUS_COLORS` constant had a doubled prefix (`GRID_GRID_STATUS_COLORS`). Fixed by correcting the reference.

**Suggestion**: These should be caught by CI. Run `npm run build:ts` in the CI pipeline on a clean checkout.

## Blocking Issue: Rust Compiler ICE

The primary blocker was an Internal Compiler Error (ICE) in `rustc` when building the `continuum-core` crate.

### Symptoms

```
error: the compiler unexpectedly panicked. this is a bug.
query stack during panic:
#0 [early_lint_checks] perform lints prior to AST lowering
#1 [hir_crate] getting the crate HIR
```

### What Was Tested

| Variable | Values Tested | Result |
|----------|--------------|--------|
| Rust version | 1.93.0, 1.94.0 (stable), 1.96.0-nightly | ICE on all |
| Features | `cuda,load-dynamic-ort`, `load-dynamic-ort` (CPU-only) | ICE on all |
| Build type | `--release`, debug | ICE on both |
| Target | `--bin continuum-core-server`, full workspace | ICE on both |
| Clean build | `cargo clean` + rebuild | ICE |
| `cargo check` | Type checking only | PASSES |

### Key Findings

- `cargo check` passes — the code is valid, only codegen crashes
- The ICE occurs during `early_lint_checks` when emitting `cdylib+rlib`
- Reproduces on `x86_64-unknown-linux-gnu` (WSL2) but NOT on `aarch64-apple-darwin` (macOS)
- NOT a memory issue (32GB available to WSL2)
- Affects both `continuum-core` and `archive-worker` crates

### Resolution

The ICE was environment-specific. On a different machine (RTX 5090 tower, WSL2 Ubuntu, Rust 1.94.0), `cargo build --release` completed successfully with 33 warnings and no errors.

The difference may be:
- WSL2 kernel version
- System library versions (libssl, libclang, etc.)
- LLVM/codegen backend differences between installs

### Recommendations

1. **Pre-built binaries**: Provide Linux x86_64 binaries for the Rust workers as a fallback
2. **CI builds**: Build and test on Linux x86_64 in CI, not just macOS
3. **Cargo.toml**: Consider whether `cdylib` crate-type is necessary — the ICE may be cdylib-specific
4. **Docker**: Provide a Dockerfile with a known-good build environment

## CUDA Toolkit (Secondary Issue)

`nvcc` was not installed, which is needed for `candle-kernels` and `cudarc` CUDA compilation. This was NOT the root cause of the ICE (CPU-only builds also failed), but is needed for GPU inference.

```bash
sudo apt-get install -y nvidia-cuda-toolkit  # ~2-3GB
```

Without the CUDA toolkit, the Rust build falls back to `--features load-dynamic-ort` (CPU-only mode).

**Note**: CUDA toolkit version must match the GPU driver version. On WSL2, the driver is the Windows host driver passed through — check compatibility with `nvidia-smi`.

## Impact on Node.js Server

Without the Rust workers, the Node.js server crashes on startup when it tries to connect to the IPC socket at `~/.continuum/sockets/continuum-core.sock`.

**Suggestion**: The server should gracefully degrade when Rust workers are unavailable — log a warning and disable Rust-backed commands, but still serve the UI and TypeScript-only functionality.

## Recommendations for `install.sh`

Based on this onboarding experience, `install.sh` should:

1. **Detect platform** (macOS/Linux/WSL2) and branch accordingly
2. **Show progress** at every step ("Installing Node.js... done")
3. **Automate PostgreSQL** setup including `pg_hba.conf` and database creation
4. **Generate barrel files** after `cargo test` produces types
5. **Verify each step** before proceeding (check `node --version`, `rustc --version`, `psql` connection)
6. **Give actionable errors** when something fails ("PostgreSQL not running. Run: sudo service postgresql start")
7. **Handle WSL2 GPU passthrough** — detect NVIDIA driver, suggest restart if GPU not visible
8. **Provide pre-built Rust binaries** as fallback when compilation fails
9. **Show estimated time** for long steps ("Building Rust workers... this takes 5-10 minutes on first run")
10. **Test the full stack** at the end — verify server starts, WebSocket connects, UI loads

## Quick Reference: Resuming After Failure

If installation was interrupted (power loss, crash, etc.):

```bash
# Enter WSL from Windows
wsl

# Check what's already done
node --version          # Should show v22+ or v24+
rustc --version         # Should show 1.94.0+
psql -h 127.0.0.1 -U $USER -d continuum -c "SELECT 1"  # DB connection
sudo service postgresql status  # PG running?

# If PostgreSQL is stopped:
sudo service postgresql start

# Navigate to project
cd ~/continuum/src

# If Rust workers aren't built yet:
source ~/.cargo/env
cd workers/continuum-core
cargo build --release --no-default-features --features load-dynamic-ort

# Start the full system
cd ~/continuum/src
npm start

# UI available at http://localhost:9000
```
